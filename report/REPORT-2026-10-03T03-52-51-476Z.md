## 主要問題與限制
1. `src/main/database/adapters/sybase/sybase-adapter.ts:87` 的 `import('msnodesqlv8')` 需要 TypeScript 解析模組；套件雖在 optionalDependencies，但此次 npm ci 後並未安裝成功／保留。執行時 catch 無法解決編譯階段模組解析問題。尚未查明選用套件未保留的底層原因，不能直接斷言不支援 macOS。
2. `tests/mcp.test.ts` 的 unauthenticated flood 測試回報 fetch failed / ECONNRESET；根因尚未定位。
3. `tests/sybase-io.test.ts` 的 ASE TLS 原始主機驗證測試綁定 127.0.0.2，當前環境回報 EADDRNOTAVAIL。
4. Electron npm 套件存在，但啟動時需要下載執行檔，本次下載未在等待期間完成；未證實 GUI 可以執行。
5. `npm run package` 使用 electron-builder --dir，只產生展開的應用，不等於 DMG 安裝映像或公開發布。package.json 雖設定 mac.target=dmg，但本次未測試 DMG 產製。對一般 macOS 外部分發仍需 Developer ID 簽章、公證及 Gatekeeper 驗證；當前沒有可用 codesigning 身分，公證憑證是否存在未檢查。
6. CI 一般驗證僅 windows-latest，沒有 macOS 建置、打包、簽章或發布工作流程。
7. npm ci audit 回報 10 項弱點（8 high、2 low）；npm audit --omit=dev 回報 2 low（DOMPurify／Monaco 相依鏈），沒有正式相依的 high／critical。未自動套用 audit fix。
8. 真實資料庫整合、Windows 專屬驗證、ASE 真機，以及完整桌面 smoke 均未通過本次驗收；略過不能視為通過。

## 建議順序
1. 修正選用原生驅動不存在時的型別解析／安裝策略，避免 ASE 選用功能阻塞全平台建置。
2. 排查 MCP ECONNRESET，調整 ASE TLS 測試的跨平台 loopback 設定，重跑測試。
3. 完成 Electron 執行檔下載，依序重跑 typecheck、test、build、test:desktop、package、test:packaged。
4. 啟動 Docker 並備妥對應原生工具後，執行真實資料庫整合驗證。
5. 加入 macOS arm64 CI／打包驗證，產製 DMG，再完成簽章、公證、Gatekeeper 與乾淨機安裝測試。
