## 實作

- `storage-bootstrap` 在 Electron ready 之前執行。尊重明確 password-store、GNOME／KDE 等已識別桌面的原生選擇；僅未知桌面的 Linux WSL 使用 libsecret 候選。其他 Linux 與 Windows／macOS 保留原有選擇，不遷移既有憑證。
- 正式 app 與 `check:secure-storage` 共用 runtime；純 MJS 與型別 wrapper 在正式 main 建置時內嵌，不依賴發行包中的開發原始碼。
- `SecureStorageService` 使用真正 availability 及固定非秘密加解密健康檢查，拒絕 basic_text；作業系統錯誤經清理，不將缺少、鎖定或不可達 keyring 誤稱為可確定的單一原因。
- humanOnly `credentials.status` 沿用現有 Command Bus／IPC sender 驗證，不增加正式讀取密碼或密文的接口。
- Settings 與密碼連線表單提供繁中／英文狀態、backend／selection source、手動安裝／解鎖指引、重新檢查與重啟提示。不由 renderer 執行 shell／sudo，SQLite／無密碼流程不被阻擋。
- 原 builder 預設 AppImage 含 sandbox bypass，且舊 runtime 依賴此環境缺少的 FUSE2。改用已安裝 builder 支援且具 checksum 的 pinned `toolsets.appimage=1.0.3`，Linux-only afterPack 安裝專案 fail-closed AppRun，desktop 為 `Exec=AppRun %U`。不修改 node_modules，不使用 --no-sandbox 或 extract-and-run。
- 新增 artifact checker 與正常 spawn＋loopback CDP／main inspector 的隔離驗收 harness；不使用強制 basic 的 Playwright Electron loader。Debug probes 僅處理自己產生的隨機合成憑證，沒有 production 測試 hook。

## 計畫差異、限制與風險

- 遵循計畫 Scope 不自動 commit/push，優先於 execute-plan 技能的預設 commit 流程；沒有 Tier 3 驗證項目。
- 首次 reviewer 具有唯讀限制，未執行測試；改由允許執行的乾淨 worker 完成必要驗證。未把未執行的檢查當作成功。
- UI／harness 的實作落差經 fix-forward 修正：健康表單顯示狀態、用 Escape 走 dirty confirmation、SQLite 精確數字為字串、退出前斷開 inspector。最終獨立檢查完整通過。
- AppImage toolset／專案 launcher 調整如上；沒有範圍擴張至 deb/rpm 或其他架構，也沒有安裝 FUSE2 掩蓋舊 runtime 問題。
- 最初不可用檢查使用受控方法故障注入，改為真正 child-only 不可達 D-Bus 後再獨立驗證；UI fixtures 僅是版面證據。
- Debugger probes 依賴 Electron 私有 IPC handler map、bundle lexical scope 與 TypeScript private field；升級需重驗，debug endpoint 僅 loopback／短期隔離 profile，不能用於真實使用者憑證。
- Ownership ledger 涵蓋觀察過的後代程序；完全在 polling 間隔內脫離而從未被觀察的後代不保證可追蹤。單元測試涵蓋已觀察後代的 escape／reparent／PID reuse。
- Linux provider 的 unknown／missing backend accessor 仍相容既有 generic provider contract；正式 wiring 傳入真正 Electron safeStorage 並拒絕 basic_text。靜態 reviewer 未發現現行正式路徑的 bypass。
- Windows／macOS、實體 GNOME／KDE 未在此輪實機驗收；策略測試不等於跨平台端到端證據。外部資料庫整合測試若略過，不能列為通過。
- 不自動安裝／解鎖 keyring、使用空密碼 keyring、basic_text／明文備援、遷移 backend 或讀取真實密碼。系統前置條件仍由使用者準備。
